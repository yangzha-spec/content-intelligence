# 第四部分：内容统计、评论复核、建议和报告

## 无需登录的验收

在本机打开 `/?preview=1&project=10000000-0000-4000-8000-000000000001&view=performance`。
固定合成数据包含 360 篇内容、1,080 次累计快照和 2,400 条评论。进入导入页选择复杂样本，实际校验 3,840 条记录。

已实现：

- 内容表现：平台、口径、日期、主题、指标筛选；精确总量、有效均值、中位数、最新累计快照、趋势、排名和缺失覆盖。
- 评论洞察：词典初筛，正向/负向/明确中性/未知分离，多标签主题、命中词、采样方式、原文搜索和结果 CSV。
- 证据建议：确定性规则生成观察、行动、证据与限制。外部 AI 可选，默认关闭。
- 报告：Markdown、包含真实表格的可打印 HTML，可在浏览器另存 PDF。
- 真实项目后端：重新读取 RLS 保护的项目源数据计算，保存输入快照、筛选、处理版本、评论初筛、洞察和报告；重复请求复用结果。

## 计算和复现边界

- 只接受单平台、单口径的指标合计。全部平台模式只做内容/评论总览，快照缺失数为不适用。
- 每个内容取截止时间前最新 cumulative 快照；不相加历史快照，不回填最新 NULL，不把 NULL 转 0。
- BIGINT 在 SQL JSON 化前转为文本；总量、均值、中位数使用 BigInt 计算。图形坐标近似显示，表格和导出保留完整数值。
- 柱形为每日发布数量，曲线为该批内容截至每日末的累计观测，不解释为每日新增流量。
- `lexicon_zh_en_v1` 是公开的规则初筛方法。未知、混合和否定表达不进入有效情感比例分母。主题允许多标签。
- 缺少评论时间的记录保留并提示；其他评论按当前日期范围过滤。热门、最新等样本不能代表全部受众。
- `analysis_runs.source_snapshot` 保存当时输入，`source_revision` 是数据库源内容的 MD5 版本指纹，不是认证签名。
- 分析、结果、评论初筛、洞察和报告在同一事务中保存；出错整批回滚。结果默认不可更新，重算建立新任务。
- 报告正文存放在 RLS 保护的数据库里，导出文件按需生成，随项目数据库记录一起级联清理。原始 Storage 文件的保留与清理仍待实现。

## 外部 AI

`analyze-project` 使用平台自带 URL/anon key 和调用用户的 JWT，保持 `verify_jwt=true`。
仅在服务端同时配置 `OPENAI_API_KEY`、`OPENAI_MODEL`，且页面明确确认本次发送和费用后调用 OpenAI Responses API。
发送范围只有汇总指标、主题计数、有效/未知评论数量和已有建议 ID，不含原始评论、标题、正文、账号或原文件。
模型仅提供行动建议，不计算指标；返回建议 ID 必须完全匹配，数字、观察、证据与限制仍来自确定性结果。
调用未完成或校验失败时明确标记失败并保留规则建议，不展示为 AI 成功。模型名称需部署者明确选择，没有默认付费模型。
目前未配置或调用真实付费模型；效果评估、生产费用控制和模型调用并发限制仍需最终接入时验证。

2026-11-04：

- 94 项自动测试通过，覆盖精度、NULL/0、快照、跨平台边界、日期、未知标签分母、报告注入防护、可选 AI 同意与失败、重复请求、权限与事务回滚。
- 类型检查与生产构建通过。

- 浏览器验证 3,840 条复杂样本校验、跨平台不混加、评论搜索与未知筛选、真实 HTML 下载及完整五组截图。

按用户要求，邮箱确认、真实 Storage 上传/下载、真实分析历史保存与真实账号 HTTP 权限验收统一留到最后。演示和模拟测试不替代这些实测。
