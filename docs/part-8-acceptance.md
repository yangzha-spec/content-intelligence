# 第八部分：评论私有草稿与恢复

## 使用方式

1. 评论洞察 → 人工复核与评估，选择评论、填写标注者/标签/主题/备注，保存本条标注。
2. 点击「保存私有草稿」（真实项目）或「保存演示草稿（本机）」。仅保存本条仍属于页面暂存，必须看到草稿确认状态。
3. 相同项目、输入、筛选和方法版本重新打开后恢复已有草稿；不会自动上传标注、覆盖原始分析或调用模型。
4. JSON 下载/载入仍可用作独立备份。切换前必须先保存草稿或下载 JSON；正在编辑的条目须先保存。

| 范围 | 保存与权限 |
| --- | --- |
| 真实项目 | 用户会话 + RLS，当前账号本人且仍有项目权限才可读，作者具备 owner/editor 权限才可写。其他空间成员，包括 owner，看不到他人草稿。 |
| 合成演示 | 当前网站来源的浏览器 localStorage，只保存明确合成数据；不调用真实草稿 API。清理浏览器数据会丢失，换来源、浏览器或设备不会同步。 |
| 范围匹配 | 项目、输入版本、筛选、评论文本/ID/归属/采样、规则结果与方法共同形成 SHA-256。数据改变后不强行套用旧标注。恢复旧范围需要打开对应分析结果或匹配输入/筛选。 |

草稿记录标签、主题、备注、自填标注者和时间、筛选/版本与指纹，不自动复制原始评论正文；备注仍可能含自行引用的原文。浏览器演示保存可能受容量/隐私设置限制，失败时仍可下载 JSON。

## 保存、冲突与故障

- 每个账号/项目/范围保留最新草稿，以数据库版本和服务端更新时间确认；第 N 版是写入计数，没有历史版本列表或回滚功能。
- 云端锁定当前作者/项目/范围的保存事务，要求预期版本匹配。直接 Data API 更新同样必须提供当前 base_revision，不能绕过旧版本保护或改写归属/服务器版本时间。
- 相同 context/annotations 的响应丢失重试只返回已保存记录，不产生新版本。服务器先提交但浏览器没收到响应时，页面保持未确认，必须重试确认或备份，不能声称丢失或已成功。
- 已知版本冲突时不覆盖：先下载当前 JSON，再读取最新草稿；文件合并若同一评论内容不同，仍整份拒绝，需逐条核对。
- 演示 localStorage 的检查属于尽力保护，不能保证多个浏览器上下文完全同时写入时的原子性；正式云端的事务锁和版本校验才提供原子保护。
- 保存/读取时暂时锁定标注控件，失败不清空当前标注；未持久保存内容与未保存条目继续触发离开保护。

## 数据库与边界

新增 `public.comment_review_drafts`，当前 14 张公共业务表均有 RLS。使用 SECURITY INVOKER RPC；没有新增服务密钥、service_role 权限或付费调用。
数据库检查 JSON 结构/字段白名单、项目、合成标记、数量/长度、标签/主题/时间，以及评论属于对应项目；非法记录整份拒绝。范围指纹仍是客户端匹配机制，不是服务端签名、标注者身份认证或可信测试集证明。
云端草稿随项目或账号删除级联清除，当前没有独立删除页面或自动过期清理；演示使用网站浏览器数据管理清理。完整个人数据删除和保留治理仍待后续实施。
不实现多人协作标注、独立盲测、争议裁决、跨范围迁移或回写已保存分析报告。正式 NLP 模型与真实效果评估仍待完成。

## 验证（2026-11-04）

- 148 项自动测试通过：新增 6 项实际 PostgreSQL 迁移/角色测试和 6 项持久草稿/真实 Supabase JS + 模拟 HTTP 测试。
- 新增测试覆盖作者隔离、viewer/anon/非成员拒绝、合法 editor、内容/评论归属校验、旧版本冲突、直接更新保护、同内容重复确认、响应丢失、存储配额/损坏和范围错配。
- 云端 `08_review_drafts_smoke.sql` 通过，所有合成用户/项目/标注都回滚，没有真实文件或 AI 调用。
- 浏览器手工标注一条合成评论，保存第 1 版，刷新恢复后编辑保存第 2 版；旧标签页提交被拒，实际下载 JSON 后读取最新草稿通过。
- 390 像素视口下文档可视宽度/滚动宽度均 375，草稿面板约 300，无页面横向溢出。
- 类型检查与生产构建通过。第 9 张截图为 V0.9 本机实际功能预览，800 条评论中只有 1 条手工演练标注；不能作为模型准确率证据。

真实账号 Data API 跨设备/跨实例并发、权限变更后的恢复和实际数据验收仍留到最终登录阶段；本次不要求用户注册。

实现依据：[Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)、[函数权限](https://supabase.com/docs/guides/database/functions)、[PostgreSQL Advisory Locks](https://www.postgresql.org/docs/current/explicit-locking.html#ADVISORY-LOCKS)。
