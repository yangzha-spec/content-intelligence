# 第三部分：原文件私有保存、确认入库与导入历史

## 使用流程

1. 登录真实账号，打开自己的项目，进入「上传并预览」。演示项目始终不能写库。
2. 选择 1 个 XLSX，或最多 3 个 CSV；一批合计不超过 20 MiB、10,000 条记录。
3. 核对字段映射，运行预览；修正所有错误，阅读指标口径和评论覆盖提示。
4. 进入「来源与入库」，填写来源名称、提供方、许可名称和说明，确认有权处理这些数据。
5. 点击「上传原文件并复核」。原文件开始私有保存；服务器重新下载、核对大小和 SHA-256，重新解析与校验。
6. 服务器通过复核后，点击「确认入库」。服务器再次复核，再在单个事务中新增账号、内容、快照和评论。
7. 在页面下方「导入历史」查看批次、状态、数量、来源、版本与文件哈希；项目成员可下载原文件。

填写许可名称不等于完成授权核验。应用写入的 `license_verified`、`public_demo_allowed` 均为 false。
没有数据的指标保留 NULL，实际为零的观测保留 0。BIGINT 在解析和传递中使用十进制字符串，避免浏览器整数精度损失。

## 重试、冲突和历史内容

- 文件清单、映射、项目时区、来源声明与处理版本构成请求指纹；同项目、同指纹复用同一批次。
- 上传中断：重新选择同一组原文件、使用相同映射和来源后重试，沿用原批次和对象路径；已存在的原文件不覆盖。
- 上传后刷新：原文件与批次保留，在导入历史中重新复核，阅读提示后再确认入库。
- 成功后重复确认：返回原批次数量，不再次新增。数据库按项目和批次加锁，避免同时写入产生重复。
- 本批任一业务记录触发外键、唯一键或数值限制时，账号、内容、指标、评论及提交状态一起回滚。失败原因独立记录在批次中。
- 新增 Posts 遇到项目已有内容键或平台内容 ID 会拒绝；当前不自动覆盖或合并旧内容。
- 为已有内容追加数据时，只提供 Metrics / Comments，或把工作簿中的旧 Posts 设为忽略。使用项目内已有 `content_key` 关联。
- 相同时间、快照类型和口径的已有快照，以及相同内容下的已有平台评论 ID，均使本批失败，不静默跳过或覆盖。
- 无稳定 ID 的相同文本评论保留，推断哈希不做唯一约束。跨批次不能保证自动判断评论是否重复。
- 文件、映射、来源发生修改时建立新批次。已有成功批次和原文件不可通过应用更新或覆盖。

## 实现与权限

- `import_batches.file_manifest` 保存 1–3 个原文件的名称、字节数、SHA-256、MIME 与系统生成路径；原有文件字段兼容保留，`file_hash` 为首个文件的哈希。
- `request_hash` 在项目内唯一；`import_config` 保存编码、项目时区和每张来源表的映射。批次身份、来源和版本由触发器防止更新。
- 三类业务记录新增 `source_table`，配合 `source_batch_id`、`source_row_number` 定位原文件和工作表。CSV 的记录号是逻辑记录号，不一定等于文本物理行号。
- `raw-imports` Bucket 为 private，只允许 CSV 和 XLSX，每个对象最大 20 MiB。上传路径必须匹配可访问批次的清单；上传还要求当前用户为该批次创建者并拥有项目编辑权限。
- 同项目成员可读原文件；非成员不可读。没有对象 UPDATE / DELETE 策略，原文件不支持客户端覆盖或删除。
- `import-batch` Edge Function 要求有效 JWT，并用 Auth 再校验用户；之后所有 Storage、Data API 与 RPC 都使用该用户会话。
- Edge Function 接收批次编号和 validate/commit 操作，不接收浏览器标准化记录或「已通过」结论。它重新读取原文件，复用前端同一套有界解析器与校验器。
- `commit_import_batch` 为 SECURITY INVOKER，只授予 authenticated 执行；继续受已有项目 RLS 限制，不使用 service_role 或新增高权限后台密钥。
- 数据安全边界是用户会话与 RLS。owner/editor 原本有项目业务表写权限；这不是对项目编辑者本人的防篡改审计系统，也不是经过外部机构验证的数据认证。

## 已完成验证

- 自动测试：74 项，覆盖原有解析/权限，以及三表事务、晚期冲突回滚、重复确认、NULL/0/BIGINT、历史关联、不可覆盖原文件、跨项目隔离、服务器重新解析、字节哈希不一致和中断恢复。
- 服务层测试使用真实 Supabase JS 客户端配合模拟 HTTP 响应；事务和策略测试使用 PGlite 执行实际迁移。模拟 Storage 不代替云端上传测试。
- 云端 `04_import_smoke.sql`：实际 PostgreSQL 用户角色、Storage RLS、事务提交、重复确认、NULL/0、非成员隔离均通过。其 Storage 行只是在回滚事务中的元数据夹具，未上传实际文件；合成用户与数据全部回滚。
- 云端服务已启动；CORS 预检返回 204，未登录 POST 返回 401。
- 页面检查：合成数据 6 条通过预览，第四步与来源表单可见，演示项目保存按钮禁用。

这些尚未实测，不能把云端 SQL 或模拟 HTTP 测试表述为完整端到端通过。不要为测试把密码、令牌或高权限密钥发到聊天中。

## 当前边界

原文件（包括失败批次）会保留；保留期限、脱敏、管理员清理及项目删除时的 Storage 联动清理尚未实现。页面目前不提供删除入口。
标准化后的事务请求另有 16,000,000 字节上限；含大量长文本的文件可能需要进一步拆分。云端超时或资源限制也不会留下半批业务记录，可查看历史状态后重试或拆分。
平台指标定义仍需核实，`pending_review` 不表示可直接进行跨平台合并统计。内容表现分析和 AI 洞察属于后续部分。
